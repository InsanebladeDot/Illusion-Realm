# 图片配方：格式与交互需求

版本：V0.1 评审稿｜日期：2026-10-28｜状态：待开发

本轮只确定需求和数据格式，不代表已有保存、应用或云端功能。适用范围为 `/create` 图片创作；不扩展到视频、音频、工具箱或全局图片预览。

## 1. 用户目标与首版决定

用户喜欢一张图的画风，希望把生成方法命名保存；以后删除原图，仍能换一套提示词继续使用。

配方像菜谱：保留锅具、火候和调料比例，拿掉这次要做的菜名。它保存的是生成配置，不保证换了提示词后画风完全一致；模型版本、LoRA 和提示词本身都会影响结果。

| 项目 | 首版建议 |
| --- | --- |
| 保存来源 | 创作页中选中的历史图片、已完成的本次生成图片 |
| 参数来源 | 该图片对应的实际 API 工作流，不能读取保存时的当前表单冒充 |
| 保留内容 | 模型、LoRA 顺序及双权重、采样参数、种子、尺寸、批量数、解码等非提示词生成参数及节点连接 |
| 删除内容 | 所有正向、负向提示词内容，以及可能携带原提示词的辅助元数据 |
| 命名 | 用户可修改默认名称；允许同名，使用稳定 ID 区分 |
| 应用行为 | 替换非提示词生成配置；保留用户当前正向、负向提示词，不自动生成 |
| 保存介质 | 本地 JSON + 独立封面；云端作为后续独立阶段 |
| 首版支持 | 本项目可识别、可完整适配的 Anima / SDXL 文生图工作流 |
| 暂不支持 | 图生图、编辑/控制流、任意第三方节点图、仅有 A1111 参数文本或无工作流的图片 |

图生图等场景往往还依赖原图、遮罩和控制图。仅保留数字参数不能保证原图删除后可用，因此首版明确提示暂不支持，后续连同依赖资源再设计。

## 2. 保存与应用流程

### 2.1 保存配方

入口：历史图片右键菜单、创作页图片详情操作区、本次生成结果的当前图片操作区，统一提供「保存配方」。入口属于创作页业务适配器，不把按钮无条件加进全局图片组件。

1. 点击时固定图片 ID / 路径及生成任务身份；切换图片不改变正在编辑的保存草稿。
2. 历史图解析该图内嵌工作流；刚生成的图读取对应任务提交快照。落盘图片可走同一解析入口，不能取最新一次任务覆盖旧图。
3. 校验工作流版本、完整性和可支持范围，复制工作流后移除提示词，不修改原图或任务快照。
4. 打开保存面板：独立封面预览、名称输入、模型/LoRA/尺寸/采样摘要、固定说明「不保存正向和负向提示词」。
5. 默认名称为「配方 YYYY-MM-DD HH:mm」，用户可修改；去除首尾空白后须为 1–60 个 Unicode 码点，禁止控制字符，允许同名。
6. 从当前图像像素重新生成封面并去除全部元数据，再提交配方。待写入完成才显示成功。
7. 成功后关闭面板并提示「已保存到本地配方」；失败保留名称和草稿，显示原因并允许重试。

保存时只要求修改名称，不增加一整套参数编辑器；之后应用到创作表单修改，再从新结果另存配方。已有配方支持重命名，不能把「编辑名称」暗中变成重写全部生成参数。

处理中禁用重复提交；同一保存草稿使用固定配方 ID，重试不得生成重复条目。关闭/取消不落盘；已经提交的写入必须等待明确结果，再允许关闭，不能取消界面后仍无提示地保存。

### 2.2 配方库

在图片创建输入区提供「配方」入口，与现有「提示词模板」区分。库内提供名称搜索、按最近修改排序，以及查看、应用、重命名、删除、导入、导出操作；首版不做标签、收藏或复杂分类。

卡片展示封面、名称、模型系列与模型摘要；选中只展开详情，不立即改表单。详情显示完整参数摘要、兼容性和独立的「应用配方」按钮。保留全量参数的 JSON 可查看/导出，摘要不能只展示现有 Meta 中的少数字段就声称完整。

- 空库：说明用途，引导从一张生成图片保存；不要提供不能完成的示例按钮。
- 加载/读取失败：同一区域提供状态、原因和重试，不把损坏数据当成空库覆盖。
- 缺图：显示占位封面，仍可查看和应用；不会回头依赖原图路径。
- 删除：确认后移除配方，再清理其独立封面，不删除原图、模型或生成历史。
- 重命名：仅变更 `name`、`updatedAt`，ID、创建时间和工作流保持不变。

### 2.3 应用配方

1. 先检查模型系列、节点支持、采样取值以及主模型、LoRA、VAE、CLIP 等依赖是否可用。模型按完整相对名称和类型匹配；同名歧义须用户明确选择，不能只按文件名猜测。
2. 显示将替换的参数摘要，明确「保留当前提示词，不会自动生成」。有未保存的参数修改时确认后再覆盖。
3. 全部校验通过后一次性提交表单配置；取消或失败不修改任何字段，不接受只更新模型、其他字段失败的半应用。
4. 保留普通与高级模式的正、负提示词草稿、分类内容和开关，不导入原图提示词。最终生成时使用用户当前模式产出的文本。
5. 默认使用配方种子；用户可沿用现有入口改为随机。尺寸、批量数等保持原值，不默认重设为 1 或取最近比例。
6. 应用后不请求生成、不清空结果、不修改输出目录、账户、服务地址、用户语言或主题。正在构建/提交生成请求时禁用应用，已提交任务继续使用自身不可变快照。

空负向提示词的提交行为沿用当前生成流程：现有构建器会填默认负向内容。配方应用不修改草稿，也不把原图负向文本带回来；最终文本应与未使用配方时同一份提示词输入的提交结果一致。

「保留全部非提示词参数」同时约束保存与执行。原图有分块解码参数，实际生成也必须保留；不能只保存完整图，应用时又从默认模板重建而丢失这些值。

当前表单不能表达的参数由受支持的配方适配层保留；最终请求除提示词、明确的模型重定位、运行期输出字段和用户后续修改外，须与配方一致。结构不兼容时禁用应用并指出原因，禁止静默降级为另一套工作流。

如果用户切换了不兼容的模型系列或生成模式，应在确认后退出当前配方绑定，明确告知将按新模式生成；不能仍显示配方已应用。普通参数修改标记「已修改」，不自动改写已保存配方。

## 3. 统一 JSON 格式

完整示例见 [recipes.example.json](./recipes.example.json)：包含 SDXL、Anima 各一条配方，使用虚构模型名称演示结构，不可直接运行。封面文件在样例中不提供。

顶层是版本化对象，`items` 是 `Recipe[]`，而不是无版本的裸 `Object[]`。单条导出仍使用同一顶层结构，只含一个成员；多条导出不改变格式。

| 字段 | 类型/规则 |
| --- | --- |
| `format` | 固定 `illusion-realm.image-recipes`，区分其他 JSON |
| `version` | 首版固定 `1`，独立于 PNG Meta 和用户文档版本 |
| `items` | 配方数组，空库为 `[]`，成员 ID 不可重复 |
| `items[].id` | UUID，名称或排序变化不改变身份 |
| `items[].name` | 按保存流程的命名规则校验 |
| `items[].createdAt` / `updatedAt` | UTC ISO 8601 字符串，修改时间不得早于创建时间 |
| `items[].kind` | 首版固定 `image.text-to-image` |
| `items[].engine` | 首版固定 `comfyui` |
| `items[].adapter` | `{ id, version }`，首版 ID 为 `sdxl-text2img` 或 `anima-text2img`，version 为 `1` |
| `items[].cover` | `{ path, mimeType, width, height }` 或 `null`；path 为受管根目录下的相对路径 |
| `items[].workflow` | 清除提示词后的 ComfyUI API 节点图，唯一生成参数来源 |
| `items[].promptBindings` | 文本插槽数组，每项 `{ role, nodeId, inputKey }`；role 为 `positive` / `negative` |

`adapter.version` 表示应用如何识别并回填工作流，不是模型版本。首版仅接受已登记的适配版本；不能靠文件名或任意字符串动态加载代码。

不额外持久化一份 `params`：它容易和 `workflow` 出现两个答案。摘要从图中读取；缓存仅在内存中存在，可重建。当前系列下未开放修改的 VAE/CLIP 等参数也保留在图内，依赖不匹配时阻止应用。

### 3.1 提示词清除规则

ComfyUI 中名为 `prompt` 的对象是整份 API 工作流，不能删除整个对象或只删顶层 `positivePrompt` / `negativePrompt`。

- 从采样器条件连接追踪正、负文本插槽，按已登记的节点/输入规则处理；不能硬编码某张图的节点 ID，也不能全局删除所有名叫 `text` 的字段。
- 支持范围内的全部提示词输入清为空字符串 `""`，保留节点和连接；生成时才向绑定槽填入用户当前文本。
- 清理结果包含已识别的全部文本槽，正、负两类均须存在；节点 ID + inputKey 不能重复，不能把同一槽同时绑定为正、负。绑定指向的节点、输入和可达连接须真实有效。
- 首版只接收已登记模板家族与其受支持变体。未知节点、未解释的字符串来源、未连接的额外文本节点或异常字段导致无法确认时，拒绝保存，不能声称已清除提示词。
- 不保存原始 Meta、提示词草稿、原图文件名/路径、任务请求对象、日志或原始 workflow 副本。去掉 `_meta` 等可含自定义文本的非执行元数据。
- 模型参数保留 ComfyUI 可识别的相对资源名称；绝对路径须按资源根明确转换，无法定位则拒绝，不能简单取 basename 丢掉子目录。
- 服务地址、密钥、凭证和设备上的输出路径不属于画风配方。存在于异常节点中时拒绝；已登记的输出字段改为适配器规定的中性值，执行时遵守当前输出策略。

除上述明确处理的字段外，非提示词生成参数与节点连接均保持原值。清理使用新对象，不能污染原图的 `prompt` / `illusionRealmMeta` 块。

### 3.2 数据校验与兼容

- JSON 从 `unknown` 开始校验，拒绝非对象、重复 ID、非法绑定、悬空引用、循环连接、不支持的节点/版本、非法数值与越界路径。
- 数字为有限值；宽高、步数、批量数、节点输出索引与种子按适配器约束校验。首版种子须为 JavaScript 安全整数，外部超范围值拒绝，不允许先损失精度再保存。
- 不支持的值不自动 clamp、替换成默认值或修改原条目。参数缺失也不能通过现有二创兜底补齐后宣称来自原图。
- 首版限制：单次导入 JSON ≤ 10 MiB、每次 ≤ 100 条、每条 ≤ 256 KiB / 200 节点；超限给出明确错误。封面导入每张 ≤ 5 MiB，解码上限 4096×4096，重新生成受管封面。
- 后续版本号高于当前时只报告不支持，保留原文件；格式升级先保留备份并验证当前及旧版样例，不改动原 PNG Meta 版本语义。
- 导入全量校验通过并确认冲突方案后才提交；同 ID 可选择跳过或生成新 ID 导入，首版不做静默覆盖。只导入 JSON 时缺失封面设为 `null`，不能读取 JSON 指定的任意本机路径。

## 4. 本地保存与独立 JSON

JSON 不会因为存在多个对象就变复杂。真正需要控制的是重复数据、整文件写入、资源生命周期与损坏恢复。

现有项目约定用户资料集中在 `illusion-realm.json`。**建议应用内配方集合复用这条读写链路，新增可选 `imageRecipes` 段，其值就是上述统一格式；旧文档缺失时为空库。** 封面属于独立媒体资源，不以 Base64 塞进用户文档。

| 用途 | JSON 与图片组织 |
| --- | --- |
| 应用内保存 | 当前用户文档的 `imageRecipes` + 文档所在目录的 `recipe-assets/<id>/<资源ID>.webp` |
| 单独备份/分享 | 独立 `recipes.json` + `recipe-assets/`；单条、多条使用同一格式 |
| 以后可选打包 | 将同样的 JSON 和图片封装为便携包；首版采用目录导出，不要求开发压缩包系统 |

这使配方脱离原图独立存在，也能单独导出 JSON；不要求每张生成图自动生成旁车文件。用户手动查看和编辑导出 JSON 是允许的，重新导入仍须完整校验。

若产品最终要求运行中也必须使用独立的 `recipes.json` 常驻仓库，应另行明确扩展根规则的单文件存储约定，并确定迁移与备份规则；本稿不把第二套读写层当成已批准实现。

### 4.1 封面与写入可靠性

- 默认保存等比缩略封面，最长边 512px，不放大；图片必须从像素重新编码，清除 EXIF、PNG 文本及其他原始元数据。复制原 PNG 或只改后缀均不合格。
- 配方封面是真实独立文件。删原图、移动输出目录后仍可查看；删配方也不影响原图。源图不可读时阻止本次保存并提示原因，不能悄悄保存成带图配方。
- 先完成新封面，再提交 JSON。JSON 写入失败清理本次新封面；崩溃残留只做有界孤儿清理。缺失封面不影响读取其配方。
- 写入由主进程串行处理，基于最新用户文档合并，避免配方、语言设置等并发保存互相覆盖；保存修改不能只提交一份旧的全量文档覆盖新值。
- JSON 临时文件与目标处于同目录，验证后替换，保留可恢复备份。Windows 文件占用/替换失败须反馈失败并保留旧文件，不能先删旧文件再赌写入成功。
- 原始用户文档损坏时停止覆盖，提供恢复/备份提示；不沿用“解析失败即新建空文档”的行为保存配方。这属于实施前必须解决的既有读写链路限制。
- 自定义用户文档位置与备份流程须带上 `recipe-assets`；迁移失败保留旧 JSON 和资源，不留指向旧机器绝对路径的封面记录。
- 首版限定 Electron 桌面能力，浏览器预览显示不可用原因，不伪装成已持久化的 localStorage 配方。

## 5. 云端与 SQLite 的边界

云端作为后续功能，用户明确选择上传才执行，不自动上传本地配方。共用配方内容格式，鉴权、权限、网络状态、同步版本与冲突保留在云端适配层，不能与本地写入方法混为同一副作用。

建议数据库保存配方 JSON、所有者、服务端修订号及图片对象键；图片二进制放对象存储。上传的是去元数据后的独立预览，原始全尺寸图片如需上传须单独说明。不会默认把整张图片二进制或 Base64 塞进业务表。

Redis 只缓存确有热点的查询结果，不是唯一存储，也不是首版必需。缓存键包含用户/权限范围与修订号，写入或删除后失效；数据库与对象存储提交完成后才报告成功，不能缓存已成功就算保存完成。

离线、失败、重试不删除本地副本。本地删除和云端删除分别确认；双向同步和冲突合并在云端阶段另立需求，本轮不增加占位上传按钮。

SQLite 适合后续出现大量配方、复杂检索、频繁局部更新或并发写入的情况。先记录条数、序列化体积与保存耗时，再判断迁移；不能把“有数组”作为迁移理由。建议在配方 JSON 达 20 MiB 或实际保存 P95 超过 300ms 时启动评估，这些是测量触发点，不是保证可承载的硬指标。

即使迁移 SQLite，交换/导出格式继续用当前版本化 JSON，封面仍用独立文件；无需为存储变化改变用户操作。实施 SQLite 前需同步更新根规则，本轮不引入数据库、ORM、Redis 或服务端。

## 6. 现有实现复用与业务边界

| 已核对实现 | 接入原则 |
| --- | --- |
| `GeneratedImageActionLayer` / `GeneratedImageContextMenu` | 创作历史图操作入口共享，通过可选回调注入保存配方；不强改其他页面业务 |
| `GeneratedImageDetailDialog` | 复用当前图片选择与解析状态，增加配方操作；不复制一套图片详情 |
| `creation-preview-tools.tsx` | 当前预览可增加可选动作，业务层绑定当前图与任务快照；具体预览调用方实施时继续核对 |
| `ResourceDialogShell` / `use-create-main-page` | 复用资源面板和创建单栏主区页机制，不另建全窗口应用外壳 |
| `library/library-card.tsx` | 优先复用卡片表面，注入名称、封面、摘要、选中与详情回调；管理动作放详情/工具栏，不硬套收藏语义 |
| `inspectImageMetaForRemix` / `parseComfyWorkflow` | 可复用文件解析、节点读取机制，但配方增加严格支持校验；现有“至少一个合法节点”的检查不能代替整图校验 |
| `remixFromInspect` / `remixFromMeta` | 不直接复用完整二创业务：它们会回填提示词、兜底缺值、归一采样器和近似宽高比，与配方契约不同 |
| `buildGeneratedImageMeta` / `saveGeneratedImages` | 从真实提交快照取源，不改变现有图片内嵌元数据和无旁车文件约定 |
| `userDataDocument` / 主进程 `storage/user-data.js` | 复用现有资料机制；补齐配方所需的并发、失败和恢复边界，不借机全仓库重构 |

统一「取源 → 严格识别 → 清除提示词 → 校验 → 保存」方法，历史图与新结果仅取源适配不同。统一应用方法服务库内各入口，保存草稿按实例隔离。

新增跨进程参数由 shared schema 定义，主进程等价手写校验；按现有 `registerHandle`、`IpcResult<T>`、`INVALID_ARGUMENT` 契约实现。不得开放任意路径读写、任意 IPC 或执行导入 JSON；导入工作流不能直接绕过适配器提交。

浅深主题、长名称、缺图、空态、加载、失败、禁用、键盘焦点和窄窗口均属于 UI 验收。文案走现有 i18n；隐藏主区页不响应 Escape；关闭返回原来的图和草稿。

## 7. 分步任务与验收

以下任务均未开始；先完成本地闭环，云端与 SQLite 不混入本轮。

| 顺序 | 任务 | 必须交付的证据 |
| --- | --- | --- |
| RCP-01 | shared 格式、图校验、清除文本和适配规则 | Anima/SDXL 当前图基线；带正负提示词输入清除后仅允许字段变化；未知节点等反例拒绝 |
| RCP-02 | 本地资料与独立封面保存 | 重启仍在；删原图仍在；JSON/图片无原提示词；并发改设置不丢字段；写入/恢复失败不覆盖旧数据 |
| RCP-03 | 历史图、详情、新结果保存入口 | 三入口调用共同流程；切图和任务交错不串数据；重试不重复；失败草稿保留 |

重点反证：源正负文本放入唯一测试标记，确认配方 JSON、导出内容、封面元数据均不存在这些源标记；同时比较工作流全部字段，不能以“没找到提示词”掩盖其他参数被误删。样例无提示词不等于清除逻辑已通过。

应用验证比较最终提交 ComfyUI 的图，而不仅比较表单显示。LoRA 分别验证顺序、`strength_model`、`strength_clip`；尺寸验证原始像素值；批量图验证每张图来源任务一致；保存期间改表单不能改变源快照。

实施时使用相关项目技能，按影响运行类型、lint、格式/IPC 校验与必要的 Electron 冒烟。业务与测试注释分别满足 70%，大白话解释，复杂逻辑使用生活类比，禁止凑数；本次纯文档不统计代码注释率。
