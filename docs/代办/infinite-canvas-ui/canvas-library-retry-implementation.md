# 新建连点与画布内删除失败修复（2026-11-12）

状态：本轮自动回归完成，人工项待验；完整仓库检查仍有既有阻塞。没有删除或改写真实用户工程，没有终止用户正在运行的应用。

## 原因与修复

只读检查现场确认：原“测试”工程已经删除，但目录表仍保留其 `directory UNIQUE` 记录；新工程可以写入同名目录，随后登记却撞到旧记录。这会留下完整工程文件但没有活动目录记录；再次尝试又可能生成带编号的目录。清理旧删除记录时，目录归属已变为新工程，也会被安全检查拒绝。两个现场工程数据库的完整性与迁移校验正常，证据不支持蒙版错误或数据库损坏。

另一个实际约束错误出现在自动找回：文件修改时间有小数，直接写入 STRICT INTEGER 时间列会失败。此前统一错误掩盖了这两类具体原因；异步等待和连点会放大表现，但并非仅靠禁用按钮就能解决。

- 复用原 SQLite 事务与目录登记：只有 `deleted=1` 且身份不同的旧记录允许让出同名目录；活动工程不被替换，登记失败事务整体回滚。
- 复用目录发现与 `.canvas-owner` 校验：合法、完整而未登记的工程重新登记；时间取整数。删除/旧资源清理前先发现这些工程，防止旧删除身份误删新作品。坏残目录不阻塞其他项目，也不擅自删除。
- 新建保存/登记明确失败时，先查询稳定身份；确认未登记才回收本次分配的目录。已提交但回执丢失按成功处理；无法核实结果时保留文件，不能误删已成功工程。
- 复用原请求防连点门闩；创建回执成功后直接更新本地列表并进入工程，不再把随后一次列表刷新失败误报为创建失败。
- 会话退出增加同步门闩，删除/关闭等待期间不重复发起操作；继续保留保存、其他挂起实例、媒体释放和共享素材保护。
- 日志仅增加动作与固定错误类别，不输出用户路径、工程名或堆栈。目录归属、数据库冲突/忙碌/结果未确认提供对应中英文提示。

本轮没有更换存储方案、修改蒙版、变更 IPC 请求形状，也没有添加后台自动删除机制。
