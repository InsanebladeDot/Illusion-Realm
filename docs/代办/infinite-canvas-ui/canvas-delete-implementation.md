# 删除画布同时释放磁盘资源（2026-11-12）

此前删除仅将目录表标为 deleted，工程文件夹与素材永远保留。本轮按用户要求改为：确认删除后，实际删除所选工程数据库、归属标记、专属素材及整个工程目录。目录表保留少量删除身份记录用于避免重新发现，不保留整份作品。不是等待后台延时清理。

## 使用与复用

- 画布菜单“删除画布”和工程库多选删除复用原确认框、CANVAS_LIBRARY 请求、保存与文件归属规则；确认文字明确为永久删除、不可撤销。
- 新增“清理已删画布资源”，清理前版本软删除留下的目录，也可继续失败后的清理。只处理目录表已删除的工程，不按文件夹名字猜删除目标，不碰未登记的普通文件夹。
- 工程库批量删除及旧资源清理要求关闭全部打开/挂起实例；画布内删除要求先关闭其他实例，且当前没有生成、文件任务或拖动。避免未落盘引用和后台写入竞争。媒体暂停并释放 src 后才请求删除；失败恢复 src，但不自动续播；成功卸载实例。
- 使用原工程引用收集器，检查图片、输入引用、导演台预览和合成素材；仍被其他活动工程引用则在磁盘修改前阻止删除。先解除引用再重试。其他活动工程不可读取时亦拒绝，不凭不完整扫描判定安全。
- 工程包导入可能另分配素材目录，连同该自有目录清理；外部原文件、旧迁移原文及备份不属于本次删除目标。全局 `library.sqlite` 和迁移记录仍保留，不能为释放某个画布而删除它们。

## 删除边界与失败

删除前按稳定工程身份验证根内路径、owner、链接和完整引用。批量先核对全部目标，任何预检失败均不执行磁盘删除；互相引用的工程一起被选中时允许同时删除。

先持久化删除意图，再清理媒体，最后删除工程数据库、owner 和空目录。这样媒体占用失败时保留可重试的工程身份；如果目录最后一步失败，尝试补回本次移除的 owner。磁盘删除无法与 SQLite 跨文件事务回滚，部分失败会明确提示，不声称文件恢复或全量成功；可再次删除或用旧资源清理入口继续。断电、恶意外部程序并发替换目录与多进程编辑冲突没有完整事务保证。

引用保护检查已保存工程。要求其他实例关闭以包含其最新状态；不会检查外部软件、其他用户库或独立备份的引用。不会将素材自动搬家或重写其他工程。清理会扫描当前工程库，尚未进行大工程规模性能测试。
