# 客户端每十帧分段

> 历史方案，已停用。当前规则见 [原帧批次与恢复原FPS](./README.md)。
按用户最新要求，使用更新后的 `utility_seedvr2_3b_int8_upscale_video.json`。保留模板里的7B模型、VAE及原处理路径；不再给图中注入旧109、106、107或ir_sample节点。

流程为：客户端连续降到10FPS → 每十帧切出一个无声片段 → 逐段上传、串行超分并保存 → 按顺序合并画面 → 合入原视频音轨 → 回填当前工程video目录和超分节点。低于10FPS的源保持其原平均帧率，不补帧。

“客户端切段”由Electron主进程异步调用随包FFmpeg，渲染层仍通过原preload方法请求；不在React线程解码整段视频。只读入当前需要上传的小片段，沿用原生成队列、取消链和临时会话清理。

## 边界帧只处理一次

先连续降帧，再在同一个编码过程中切段，不能把0–1秒、1–2秒分别重新解码并各自取整。

| 片段 | 实际帧编号 | 半开范围 |
| --- | --- | --- |
| 0 | 0–9 | [0,10) |
| 1 | 10–19 | [10,20) |
| 2 | 20–29 | [20,30) |
| 尾段示例 | 20–22 | [20,23) |

1秒时刻对应第10帧，只在第二段处理，不把它作为第一段的附加尾帧。每十帧设置一个关键帧，分段器在该关键帧之前切开。片段使用H.264 CRF0；YUV420格式内不新增有损压缩，奇数尺寸按既有规则补齐到偶数。准备回包为 `{path,startFrame,frames}` 列表，以真实片段帧数为准；尾段不补满十帧。

超分结果仍需逐段通过帧数、FPS、尺寸一致性检查，才允许合并；合并继续重排时间戳，音轨从原视频取出。临时片段和中间结果只存在本任务系统临时目录，正常完成、失败、取消或所属窗口退出时清理；原视频不删除。
