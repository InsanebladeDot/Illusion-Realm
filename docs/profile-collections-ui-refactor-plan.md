# 我的主页与收藏夹 UI 重构处理文档

日期：2026-10-15  
状态：待实施。本次只整理处理方案，不修改页面、导航或接口代码。

### 补充确认：应用外壳的视觉关系

用户进一步明确的要求优先于下文较宽泛的样式建议：

- 浅色模式下 main 是纯白内容面板，圆角范围 5–10px，预览和默认实施值为 **8px**，不用 16px 以上大圆角。
- head（全局顶部栏）与 nav（左侧导航）使用完全相同的背景色，构成连续的 L 形底色；不使用两块略有不同的颜色。
- head 底部与 nav 右侧不画分隔线，不画拼接缝或各自的阴影；通过 main 白色表面与外围留白区分内容。
- 不改 nav 的菜单、顺序、路由、图标及账户菜单功能；仅按已约定移除 nav 顶部重复 logo 和伸缩箭头。去除分隔线、统一外壳底色属于本条新补充的视觉要求。
- 标题栏现有功能保留，不照搬参考图新增全局搜索。
- 本组预览采用中性浅蓝灰外壳，避免紫色。白色 main 指浅色模式；深色模式仍按项目主题提供深色表面，不能整块强制白色刺眼。
- 预览中作品图来自用户提供的参考图裁切，仅为说明结构，不会写入真实账户或上传云端。

## 3. 页面整体结构

```text
全局标题栏（保持现有能力与最高层级）
├─ nav（仅上述两项移除，其余不变）
└─ main：我的主页内容面板
   ├─ 封面横幅
   │  └─ 更换封面 / 编辑公开资料
   ├─ 头像 + 昵称 + 简洁统计
   │  └─ 当前用户的邮箱等账户资料
   ├─ 内容标签：帖子 / 喜欢 / 评论 / 收到的评论 / 私密统计 / 云端图片 / 收藏夹
   └─ 当前标签内容
      ├─ 标题 + 说明
      ├─ 我的 / 公开 + 网格 / 列表
      ├─ 收藏夹卡片或列表行
      └─ 加载更多 / 状态反馈
```

采用 main 内一个纵向滚动区域，封面、资料、标签和收藏夹共同滚动；不在每一层再增加独立滚动条。标题栏和 nav 留在现有应用外壳中。

参考图底部的「视觉概念稿」说明不属于正式页面，不加入产品。卡片超出可见区域后通过 main 滚动查看，不能固定裁掉最后一排。

## 4. 具体需要重构的区域

### 4.1 主内容容器

现状：个人资料、登录状态和内容标签各有自己的间距与容器，整体更像几块独立内容。

处理：

- 把个人主页统一放进一个圆角内容面板，封面、资料、标签、卡片共用左右对齐线。
- 宽屏面板外边距建议 12–20px，内边距 24–28px；窄屏减少为 12–16px。
- 使用项目现有背景、表面、边框和文字主题变量；背景与内容面板有轻微层次即可。
- 改动优先限于 `/profile`，不为了这一页改变其他页面的全局布局与滚动策略。
- main 承担剩余高度，所有滚动容器正确设置 `min-height: 0`，防止内容把窗口撑高。

### 4.2 封面横幅

现状：`ProfileHeader.tsx` 只有头像、资料与编辑按钮，没有封面。

处理：

- 增加横向封面，宽屏高度建议 160–180px，中等宽度 140–160px，小屏 120–140px。
- 图片使用 `object-fit: cover`；展示裁切只影响预览，不修改原图。
- 封面内右上角放「更换封面／背景」「编辑公开资料」，使用统一高度的小按钮。
- 没有封面时显示中性纯色或项目主题允许的低对比背景，不加载示例图冒充用户封面。
- 更换封面复用已有文件读取、校验与裁剪能力，补充取景预览与重置入口。
- 封面持久化属于后续实施项：当前 `UserProfile` 没有封面字段，不能声称已有云端同步能力。
- 首版建议本地保存，明确其设备范围；若新增用户文档字段，要补默认值和旧文档兼容。

### 4.3 头像与身份资料

现状：桌面头像为 128px，昵称、邮箱和编辑按钮占据较大的独立区域。

处理：

- 头像改为叠放在封面下边缘，宽屏约 76–88px，小屏约 64–72px，保留清晰的表面色外圈。
- 昵称放在头像右侧，统计以小字号跟随；不使用大块统计卡片。
- 继续优先读取真实登录昵称，游客使用本地资料，不固定写成 `guest`。
- 保留此前要求的昵称下邮箱、账户 ID 和验证状态，只对当前登录者展示，不因为参考图省略了就删除。
- 长昵称、长邮箱和中文／英文混排可换行；昵称不把按钮挤出容器。
- 头像编辑继续复用现有圆形裁剪预览和滚轮缩放，最终仍保存正方形图片。
- 粉丝、关注等没有服务端真实统计时，不将本地占位数字包装成实时云端数据，不提供无效跳转。

### 4.4 当前账户／游客状态

现状：`GuestSessionStatus` 是横跨主页的一张独立卡片，增加纵向占用。

处理：

- 已登录时将重复的「当前已登录」提示收敛到资料区域，避免与昵称重复占一整行。
- 退出能力继续由已有账户菜单提供，不删除真实退出逻辑。
- 游客状态、到期及重新登录提示仍清楚可见，不能为了简洁隐藏有效期相关反馈。
- 此调整仅针对主页上的重复展示，不改登录、游客一小时规则及账户认证。

### 4.5 内容标签栏

现状：标签间距较大；网格／列表按钮只出现在帖子占位区域，与收藏夹没有联动。

处理：

- 保留现有标签及语义，不在此次顺便开发帖子、评论和关注系统。
- 视觉高度收敛至约 44–48px，选中项使用主题强调色细下划线与适度字重。
- 「云端收藏夹」可简化显示为「收藏夹」，接口和内部资源类型不改。
- 窄屏标签保持单行横向滚动，不强行压缩文字或多行堆叠。
- 切换标签时保留该标签的浏览状态；上传失败的草稿与 requestId 不能丢失。
- 账户发生变化后仍清空上一账户的私有列表，沿用现有隔离逻辑。

### 4.6 收藏夹标题与工具条

处理：

- 左侧为「收藏夹」标题和简短说明；右侧为「我的／公开」与「网格／列表」。
- 「我的／公开」复用 `CloudScope`，游客不能进入我的私有资源。
- 网格／列表切换复用项目已有按钮样式和状态模式，不重新造一套选择器。
- 「新建收藏夹」保留为当前用户可见的操作；空间不足时换到工具条下一行。
- 按收藏夹 ID 查询保留，但收进次级操作，避免大输入框长期占据主要视觉区域。
- 切换布局只改变显示方式，不重新拉一遍同一份数据，不清空分页和当前选择。

### 4.7 收藏夹网格：图 1、图 3

现状：收藏夹只有边框文字卡片，没有图片封面。

处理：

- 每张卡片使用同一套结构：封面 → 名称与创建者 → 描述。
- 卡片以图片为主，减少外围粗边框，封面圆角建议 8–12px。
- 宽屏采用三列，间距约 18–20px；卡片标题和说明左对齐。
- 图 1 的宽屏封面约为 2:1；图 3 的中等宽度可采用接近 1:1，以保留人物画面。
- 以内容区域的实际宽度决定列数，卡片最小宽度建议 220px；不足时自动降为两列或一列。
- 图 3 的三列成立是因为主内容仍足够宽，不代表手机也强制三列。
- 名称超过可用宽度省略并提供完整文本；描述最多两行，空描述不补假标签。
- 整张封面与名称均可进入收藏夹；更多按钮不触发卡片跳转。
- 图片加载失败显示中性占位与收藏夹名称，不能留下破图图标或固定使用示例图片。

### 4.8 收藏夹列表：图 2

处理：

- 同一份数据渲染为列表行，不另建业务数据源。
- 行结构为：小封面 → 名称与描述 → 创建者 → 更多操作。
- 宽屏缩略图建议约 144 × 88px；行间使用低对比细分隔线，避免每行套厚卡片。
- 中等宽度创建者可移到名称或描述下面；手机缩略图约 88 × 64px。
- 更多菜单中只放已实现且有权限的操作，自己的收藏夹可管理／删除，他人的不显示这些操作。
- 删除继续要求知晓确认；删除收藏夹不会删除原图片。
- 不加入文档未提供的「复制分享链接」「下载全部」「批量删除」等新业务。

### 4.9 收藏夹详情

现状：选择收藏夹后直接在列表下面继续堆详情，页面容易很长。

处理：

- 优先采用同一内容区域中的详情视图，显示返回入口、名称、说明和图片列表。
- 返回列表时保留我的／公开、网格／列表、已加载页和滚动位置。
- 复用已有 `CloudImageGallery` 与大图预览，不另写图片缩放、拖动和预览逻辑。
- 保留取消收藏、权限失效提示、游标分页和修订冲突后回到第一页的逻辑。
- 退出详情不需要新增路由；本次保持 `/profile` 路由稳定。

### 4.10 云端图片标签

- 保留上一轮已经完成的概览、搜索筛选、上传弹窗和图片管理能力。
- 与新的主页统一边距、圆角、字体层级，避免在外层内容面板中再叠很多同样的边框。
- 收藏夹卡片与图片卡片共享基础排版样式；两类资源的权限、字段和操作依旧由各自业务层提供。
- 名称搜索仍只针对已加载内容；完整 ID 可调用详情接口，不宣称支持后端全库名称搜索。

## 5. 参考图需要的数据，从哪里来

以 `docs/frontend-handoff/frontend-image-upload-api.md` 和账户文档为当前接口事实来源。

| 展示内容 | 当前数据情况 | 首版处理方式 |
| --- | --- | --- |
| 收藏夹名称、说明、公开／私有 | `CollectionView` 已提供 | 直接使用接口字段 |
| 收藏夹 ID、所有者 ID、revision | 已提供字符串 | 原样使用，不能转为 JS number |
| 收藏夹封面 | 无 `coverUrl`、无封面设置接口 | 从当前可访问内容中选择第一张有效图片，失败用占位 |
| 收藏夹创建者昵称 | 只有 ownerId，没有作者昵称 | 自己的显示当前账户昵称；其他显示用户 ID，不写假名字 |
| 收藏夹标签 | 没有 tags 字段 | 展示 description，空值不补示例标签 |
| 收藏夹图片总数 | 当前列表未返回总数 | 首版不显示总数，不能拿第一页长度当总数 |
| 个人主页封面 | 本地与账户格式均未提供 | 作为本地外观扩展规划，云端同步暂不承诺 |
| 头像 | 当前为本地头像；账户接口不返回 avatarUrl | 沿用现有实现，不冒充服务端头像 |
| 创建者公开资料 | 当前不能按任意 ownerId 读取昵称 | 不新增未经文档支持的请求 |
| 顶部全局搜索 | 参考图有，当前没有统一搜索契约 | 本轮不新增占位输入框，保留现有标题栏 |

封面读取要控制请求数量：只对进入可视区域的卡片读取预览；先尝试 `items?size=1` 和对应图片详情，最多四张卡片并发，不能为每张封面读取整本收藏夹。缓存按账户、收藏夹 ID 和 revision 隔离，内容变更、公开范围切换及账户退出时失效。

若第一项在读取过程中变为不可访问，允许有界尝试后续少量内容；达到上限或没有可访问图片就使用占位，不无限翻页。预览失败不阻断收藏夹文字列表与点击进入。

现有 `getCloudCollectionItems` 客户端固定每页 24 项。若实施小预览请求，应通过扩展同一类型化客户端及其校验完成，不新增一个绕过 IPC 的任意 URL 请求器。

## 6. 响应式处理规格

按 main 内可用内容宽度设计，不能仅看屏幕宽度：展开 nav 后的剩余空间才是实际排版空间。

| 内容区域宽度 | 收藏夹网格 | 资料与操作 | 列表 |
| --- | --- | --- | --- |
| 960px 及以上 | 三列，封面偏横向 | 横幅右上操作；头像、昵称、统计尽量同一行 | 封面、文字、创建者、更多同一行 |
| 720–959px | 三列，封面可接近正方形 | 操作不遮挡头像；长昵称可换行 | 创建者在文字区或右侧按空间显示 |
| 480–719px | 两列 | 标题工具条允许换行 | 缩小缩略图，优先保留名称 |
| 480px 以下 | 一列 | 横幅操作可移到横幅下；标签可横向滚动 | 创建者下移，更多按钮始终可点 |

- 以上是内容断点建议，实施时优先使用容器尺寸或现有媒体查询方案验证。
- 高度不足只滚动 main，不缩小所有字号硬塞满屏。
- 有底部导航时预留底部安全间距，最后一张卡片和分页按钮必须能完整滚入视口。
- 弹窗复用现有外壳，顶部避让 `--window-chrome-height`，不能覆盖窗口按钮。
- 布局切换、窗口缩放和系统缩放都不能产生整页横向滚动。

## 8. 分阶段实施顺序

1. **主页骨架**：统一内容容器、封面、头像和资料区域，保持 nav 限制。
2. **收藏夹工具条**：标题、我的／公开、网格／列表、次级操作。
3. **两种资源排版**：同一批数据切换卡片和列表，先完成真实字段与占位展示。
4. **封面预览**：按可视区域读取，限制并发，补缓存隔离和失效处理。
5. **详情与管理**：返回列表保留状态，复用现有编辑、删除确认和图片预览。
6. **适配与验证**：浅色／深色、窄屏／矮屏、长文本、错误和权限变更。

实施中如发现接口缺字段，先采用本文件约定的回退；新增后端字段、全局搜索或新导航入口，另列需求，不夹带进视觉重构。

## 9. 验收清单

- nav 菜单、底部账户菜单、现有路由和标题栏任务入口与改动前一致。
- nav 只移除约定的 logo 与箭头；手动伸缩入口的最终方案要先确定。
- 封面、资料、标签和收藏夹左右对齐；宽屏没有多个大边框反复嵌套。
- 网格／列表展示同一批收藏夹，切换不重复请求、不丢页、不更改公开权限。
- 图 1 的宽屏三列、图 2 的列表、图 3 的中等宽度均有对应布局。
- 390px、320px 内容不横向溢出；高度不足可滚动到最后一项和分页按钮。
- 以现有展开／收起 nav 状态分别验证主区，不为了复刻截图擅改 nav。
- 图片加载前后无明显跳动；无封面、空收藏夹、图片失效均有可用回退。
- 原有 PNG 上传、UUID 重试、元数据保留、编辑修订检查、删除确认和取消收藏功能不回归。
- 公开列表不泄露私有封面；退出或换账户后不沿用旧账户的预览缓存。
- 所有按钮键盘可操作，有清楚的焦点、选中态与可访问名称。
- 浅色／深色遵循项目主题，无固定紫色；文案通过现有 i18n。
- 构建、类型、lint、文案检查及相关冒烟通过；冒烟使用当前源码构建，单独执行。
