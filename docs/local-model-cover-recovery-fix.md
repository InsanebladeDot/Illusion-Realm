# 本地模型 SHA256 补图修复

实施日期：2026-10-31。范围仅为工具箱 C站本地模型的单项、批量资料补全；保留工作区已有修改。

## 原因与修复

原哈希查询仅接受 `type=image` 且 `nsfwLevel=1` 的图片，没有使用用户在 C站页面保存的内容访问偏好。旧响应缺少等级或媒体类型时也会被过滤。即使有多张有效候选，也只尝试第一张，首图失效便直接返回封面失败。

现在按已有内容偏好选图，默认关闭时仍过滤明确受限图片；等级缺省或为 0 时与在线页面规则一致。缺省媒体类型仅接受明确图片扩展名，显式视频始终拒绝。

按准确版本合并哈希接口与父模型详情中的图片，去重后最多尝试 6 张。每张最多等待 10 秒，整组使用 30 秒截止信号；网络失败或无法解码时继续下一张，成功后立即结束。不会借用其他版本的封面。

沿用 `remoteLogo`、`saveLogo`、扫描器和原有封面可用性检查。图片采用原下载器传输、20 MiB 限制、原生解码和无覆盖 PNG 提交；模型本体仍流式计算 SHA256，不上传权重。不新增 IPC、共享类型、持久化格式或图片展示组件。

已有来源 JSON 但缺少封面时继续查询补图，来源 JSON 保持原字节。单项完成后刷新和批量结束后重扫的现有逻辑已验证，无需改写前端业务。

## 使用与限制

完全退出并重新启动应用以载入主进程修改。安装版需要使用包含此次修复的新构建，单独刷新界面或重启旧 exe 不会获得修复。进入本地模型，显式运行单项补全或批量补全；当前会话中已有未完成批次可点击重试未完成项。已有 JSON 但没有封面的模型会继续补图。

站点未收录、当前偏好下没有图片、下载失败仍分别反馈具体状态。已有有效自定义封面保留；已有损坏同名 `logo.png` 不擅自覆盖，需用户通过原更换封面入口处理。

未验证：全库逐项公网补图、已安装 exe 分发产物、慢 CDN 的真实超时边界。界面测试的文件符号链接用例因系统权限跳过；服务测试的目录 junction 越界用例通过。没有执行鼠标拖入或遮挡验证，本次补图改动不涉及这些交互。
