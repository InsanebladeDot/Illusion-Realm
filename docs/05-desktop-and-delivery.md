# 桌面体验与本地数据

用户希望在首次安装时看清依赖与状态，在日常使用中保持导航一致，升级和重开后恢复数据及语言。

- 安装与修复入口负责 Windows Setup 和依赖清单，主窗口展示下载状态和窗口历史。登录、个人页和设置共用应用外壳，统计区应如实呈现无历史数据的情形。
- 首帧语言由 preload 同步提供，应用随后按用户文档水合。窄窗与重新获得可见性时重新读取实际显示条件。
- 生成小票、画布草稿与快捷词迁入 SQLite。偏好继续由用户 JSON 保存，下载队列使用单独数据库。迁移必须可备份、回滚当前事务并核对内容。
- 静态导出与安装资源沿用 Electron 应用协议。

## 首帧语言与响应式布局

- 首帧语言解析同时决定界面语言和 `lang`。主进程注入原始 `--illusion-locale=` 参数，preload 提供同步快照。缺失或非法值回退 `zh-CN`，合法 `en` 作为首帧。文档就绪后允许一次从快照到文档的启动切换。
- `matchMedia` 事件、窗口 resize 和可见性变化触发重新读取 `.matches`，监听器随组件或订阅销毁清理。

## 数据归属与恢复

| 数据 | 权威存储与范围 |
| --- | --- |
| 生成小票、快捷词、画布草稿 | 用户 JSON 同目录、同名前缀的 SQLite 库，保留原 USER_DATA IPC 形状 |
| 设置、账号偏好和首帧语言 | 实际用户 JSON |
| 凭据 | 原专用服务 |
| 下载队列、恢复信息与文件归属 | Electron userData 下单独的 `model-download-queue.sqlite` |
| 图片、音频、视频、模型 | 原媒体文件路径，业务表保存引用和归属 |

### 迁移模板

1. 锁内确认权威来源，保留旧 JSON 的原字节备份。拒绝坏源和无法完整理解的输入。
2. 校验领域结构，通过 `BEGIN IMMEDIATE` 与参数绑定写入拆分后的节点、边、引用、小票及槽位。复杂工作流参数与外嵌工具文档使用版本化附表。
3. 按原文档形状反读比对，确认等值性后提交并切换权威来源。失败时回滚本次 SQL 事务。
4. 旧生成小票只迁移原有事实。保持媒体、PNG Meta、`.ircanvas` 与模型文件契约。结构版本由 `apps/electron/src/main/storage/sqlite` 的迁移文件决定。

### 恢复边界

SQLite 与设置 JSON 分属两个文件，分别提交。部分失败要明确通知调用方，并允许按原接口重试。重大故障先关闭应用，保留数据库及匹配的 WAL/SHM 整体副本，再用旧字节备份对照恢复。迁移完成后由支持 SQLite 的版本继续写入。

## 安装与账户接口模板

- `pnpm build` 生成静态导出、桌面资源和安装包。`pnpm build:setup` 使用以前的客户端安装引擎重新封装向导。`pnpm build:setup:native` 构建当前客户端并生成原生 NSIS 安装包。
- 账户快照接口使用 `/api/v1` 前缀。注册、邮箱验证、登录和刷新按各自请求体发送，受保护的资料、会话和图片管理接口附 `Authorization: Bearer <accessToken>`。部署地址由后端提供，Electron 使用受控主进程 API 处理令牌。

```http
GET /api/v1/account/me
Authorization: Bearer <accessToken>
```
