# 功能与测试注释规范

遵守根目录 [AGENTS.md](../../../AGENTS.md)。面向初级程序员，用大白话说明代码做什么、怎么用、能提供什么。

## 写法

- **用途、用法、结果按需说明。** 写清不明显的职责、调用条件、输入、返回值或副作用；不强制每处写齐三段，不复述名称和类型。
- 简单逻辑一句话说清；代码已清楚表达时不另加说明。复杂逻辑必须用简短生活类比，并点明对应机制，不能只讲故事。
- 异步和资源处理补充失败由谁接住、如何取消和清理；测试说明场景、预期及 mock 未覆盖的真实行为，共同前提集中写。
- 共同机制解释一次，调用处只写差异。SQL 只补充实体关系、特殊字段含义与约束原因，区分数据库保证和调用方负责的规则。
- **禁止废话、重复和凑数。** 不写“定义变量”“返回结果”等语法翻译，不刻意拆注释或压代码。任务进度放文档，注释不得把计划写成现有能力。
- 界面使用处标注中文区域名；`"use client";` 保持第一行，文件头说明放在其后。

例如：

```ts
/** 按素材编号查询登记记录；返回记录或 null，不读取磁盘。 */
```

复杂机制例如：“把哈希当作内容指纹，用 Map 按指纹登记，让相同内容共用一条记录。”类比和真实机制在同一句中说明，不在各调用处重复。

## 统计口径

`注释率 = C ÷ (C + B) × 100%`，C 为有效纯注释行，B 为非空代码行。

- **业务与测试分别以 20%–30% 为参考范围，按任务汇总，不逐文件、函数或表硬凑。** 低于范围检查是否漏掉必要说明，高于范围检查是否重复；内容准确完整时允许偏离，报告原因，不为比例补废话或删除必要解释。
- 先确定本次任务基线，保留已有修改；新增文件统计全文，修改文件仅统计本次新增及替换后的行，删除行与未变更上下文不计。不能扩大修改范围补比例。
- 各语言按语法识别注释；多行注释仅有有效内容的物理行计入 C，空行、装饰线、单独定界符及无效说明不计。独占一行的 JSX 注释容器按内容判断；字符串、URL、正则里的注释符不算注释。
- 代码与注释混合行只计入 B；import、类型声明、括号行均计入 B。JSDoc 不重复类型凑数，先剔除无效注释再计算。
- 测试夹具、验证及冒烟脚本归测试侧，其他功能辅助脚本归业务侧；SQL 按用途归类。文档及其中的示例不算源码；纯文档变更或某一类无可统计行时报告“不适用”，不写 100%。

## 交付前核查

核对注释与真实行为、输入输出、错误及清理边界是否一致。逐文件记录 C、B，分别汇总业务和测试；文本扫描仅提供候选数量，未经人工复核不称为有效注释率。

交付简述统计基线、范围、方法和两类结果；偏离参考范围时说明原因。实际测试和未验证项如实报告，不把注释率当成功能正确的证明。
