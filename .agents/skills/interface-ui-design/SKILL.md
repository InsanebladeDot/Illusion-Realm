# UI 设计与任务边界

遵守根目录 [AGENTS.md](../../../AGENTS.md)。先明确用户目标、操作流程、输入输出与状态变化，再决定布局和实现；仅评估的请求只给评估，局部修改不扩大为全局设计系统重做。

## 从现有实现出发

- 阅读目标页面、真实调用方及主题样式；用户指定 Card、弹窗或功能组时，以该实现为基准。
- 先查 `apps/next/src/components/library/library-card.tsx`、`apps/next/src/components/ResourceDialogShell.tsx` 等相关公共实现，按任务选择，不默认改这些组件。
- 同类 UI 的参数、插槽与业务边界遵守 [ui-parameter-reuse](../ui-parameter-reuse/SKILL.md)；实现前简述复用基准、注入差异及独立业务。
- 字体、颜色、间距、圆角和动效沿用既有语义变量；只有现有规范不能表达当前需求时才补充。不给局部任务另建配色、组件库或全局 CSS 覆盖体系。
- 保留真实数据、路由、权限和事件处理。调整公共 API 时接通本次相关调用方，不以静态数据或模拟成功替代业务。

## 交互与布局

- 按变更覆盖加载、空态、错误、禁用、选中、长文本、缺图与重复操作；反馈应靠近触发动作。
- 保持语义化控件、可见焦点和键盘路径；弹窗验证焦点进入、关闭和返回，避免点击遮罩误触内部操作。
- 依据现有窗口约束处理普通、全屏与窄窗口；检查滚动归属、关键按钮可达性和浮层裁切，不靠整体缩放或随意隐藏溢出掩盖问题。
- 保留 Electron 标题栏拖拽区与可交互区边界；动画遵守减少动态效果设置。
- 主题、媒体查询和弹窗首帧使用 [nextjs-renderer](../nextjs-renderer/SKILL.md) 中的现有机制。

## 验证与交付

公共组件变更验证相关入口；存在多个调用方时至少验证两个，检查样式同步与数据、操作相互独立。按变更检查深浅主题、窄窗口、键盘与异常状态，结合真实运行或截图确认效果。

交付说明复用基准、已接入场景、保留的业务差异、实际验证与未验证项。代码检查通过不能代替交互验证；代码注释遵守 [comment-coverage](../comment-coverage/SKILL.md)。
