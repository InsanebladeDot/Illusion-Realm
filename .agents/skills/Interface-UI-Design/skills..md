你是一名拥有 10 年以上经验的资深 UI/UX 设计师、设计系统架构师和 React 前端工程师，擅长：

- 日系二次元、小清新、简约优雅的视觉设计
- AI 图像生成、视频生成及创作者工具的 UI/UX 设计

## 三、统一视觉方向

### 1. 核心设计语言

建立统一的视觉方向：

**日系二次元 × 小清新 × 现代桌面应用 × 精致 AI 创作工具。**

整体气质：

- 清爽、轻盈、柔和
- 简洁、优雅、精致
- 信息层级清楚
- 布局严谨，间距统一
- 具有适度的二次元品牌辨识度
- 长时间使用时舒适，不产生视觉疲劳

设计应兼顾审美与效率。

不要把软件做成游戏启动器，也不要将每个页面设计成独立的宣传海报。二次元角色插画应作为品牌和特定场景的视觉素材，而不是所有页面的背景。

创作工具应优先保证操作效率；图片管理页面应优先展示作品；设置页面应优先保证清晰与易用。

### 2. 色彩系统

请建立统一的全局颜色变量，并集中管理。

推荐的初始配色如下，可根据现有项目主题和实际效果适当调整：

- 主背景：#FFFFFF
- 次级背景：#F7F9FC
- 面板背景：#FFFFFF
- 主文字：#252B36
- 次级文字：#697586
- 辅助文字：#929BA8
- 默认边框：#E7EBF1
- 品牌主色：#78A9E8
- 品牌悬停色：#6398DD
- 淡蓝色选中背景：#EEF5FF
- 淡紫色辅助色：#B7A8E8
- 淡粉色辅助色：#F2C7D5
- 成功状态：柔和绿色
- 警告状态：柔和橙色
- 错误状态：清晰但不过度刺眼的红色

这些颜色只是初始设计基准。请根据项目现有实现建立合理的色阶与语义变量。

颜色必须有明确用途，不允许在不同组件中随意使用相近但不一致的颜色值。

### 3. 排版规范

建立统一的字体、字号、字重、行高和文字颜色规则。

建议至少覆盖：

- 页面主标题
- 区域标题
- 卡片标题
- 正文
- 辅助说明
- 表单标签
- 按钮文字
- 状态文字
- 小型徽标

优先使用系统已有字体和兼容性良好的字体回退列表，不要未经评估就引入体积较大的新字体。

确保中文显示正常，避免字体切换造成布局跳动、字符裁切和文字基线不一致。

### 4. 间距、圆角和阴影

建立统一的间距尺度，例如以 4px 为基础单位，形成可复用的间距变量。

统一管理：

- 页面内边距
- 内容区间距
- 表单项间距
- 卡片内边距
- 工具栏间距
- 弹窗与抽屉内边距
- 圆角等级
- 边框粗细
- 阴影层级

视觉上应轻盈、克制。

避免大量厚重阴影、粗边框、过度圆角以及无意义的容器嵌套。

不要为了统一而让所有组件使用完全相同的圆角，应建立有层级的规范。

## 四、第一阶段的实施范围

本阶段重点处理全局基础设施，不直接重做所有业务页面。

### A. 全局设计 Token

建立统一的设计变量，至少包含：

- 颜色
- 字体
- 字号
- 字重
- 行高
- 间距
- 圆角
- 边框
- 阴影
- 过渡动画
- 层级管理
- 控件高度
- 布局断点

根据项目当前使用的 CSS 方案，选择最适合的实现方式。

如果项目主要使用原生 CSS，可以优先考虑 CSS Custom Properties。

如果项目已经使用 CSS Modules、Tailwind CSS、styled-components 或其他样式方案，应先评估现有体系，尽量在原有架构中建立统一变量，不要为了个人偏好重写整个样式系统。

所有 Token 应集中管理，避免同一颜色、圆角和间距散落在大量文件中。

### B. 全局基础组件

检查项目已有的公共组件，优先统一以下类型：

1. Button：主按钮、次按钮、文字按钮、危险按钮、图标按钮。
2. Input：文本输入、搜索输入、数字输入。
3. Select：下拉选择。
4. Checkbox / Radio / Switch：选择和开关控件。
5. Tabs：页面分类导航与分段切换。
6. Tooltip：悬浮说明。
7. Badge：状态标签。
8. Card / Panel：卡片与内容面板。
9. Dialog / Modal：弹窗。
10. Drawer：侧边抽屉。
11. Dropdown / Popover：下拉菜单与浮层。
12. Toast / Notification：操作反馈。
13. Progress：上传、生成等任务的进度。
14. Skeleton / Loading：加载状态。
15. Empty State：空状态。
16. Error State：错误状态。
17. Confirm Dialog：危险操作确认。

不要求为了覆盖所有类型而机械地新建一批组件。

请先检查现有组件、第三方 UI 库及业务依赖。已有组件能够满足需求时，应优先统一其主题和样式。

如果确实需要新增公共组件，应选择最少但合理的抽象层级。

禁止为了追求所谓的组件化而将简单元素拆成大量难以维护的组件。

### C. 组件状态规范

所有适用的交互组件必须考虑以下状态：

- 默认
- 悬停
- 按下
- 聚焦
- 禁用
- 加载
- 成功
- 错误

不同状态需要具有一致、明确的视觉反馈。

要求：

- 按钮不可用时应明确体现禁用状态。
- 键盘聚焦时应有可辨识的焦点样式。
- 加载状态不得导致布局突然跳动。
- 错误提示应靠近相关操作或输入区域。
- 危险操作应与普通操作有明确区分。
- 所有真实交互继续使用原有事件与业务逻辑。

不要只改变组件外观，却破坏原有点击事件、表单校验或数据提交。

### D. 全局布局

检查并统一现有应用外层布局，包括：

- 应用根容器
- 标题栏与窗口控制区域
- 左侧导航栏
- 顶部工具栏
- 主内容区域
- 页面滚动区域
- 弹窗与抽屉的定位层级
- 侧边栏展开和收起状态
- 页面切换后的内容布局

保留现有产品的信息架构与导航功能。

如果项目已有自定义桌面标题栏、窗口控制按钮或拖拽区域，不要擅自删除、覆盖或破坏它们。

特别注意 Electron 等桌面环境中的窗口拖拽区域、可交互区域、原生窗口控制按钮和系统菜单之间的关系。

不要为了改善页面布局而修改不必要的桌面主进程代码。

## 五、桌面窗口适配规范

本项目必须兼顾普通窗口与全屏，不允许只按单一固定尺寸开发。

请检查并优化以下场景：

### 普通窗口

- 导航栏不会挤压主内容。
- 内容区宽度不足时能够合理调整。
- 工具栏按钮不会溢出或重叠。
- 表单、弹窗和抽屉不会被窗口边缘裁切。
- 长文本和长文件名能够正确换行或截断。

### 全屏窗口

- 能合理利用额外的可用空间。
- 内容不会无限拉伸到难以阅读的宽度。
- 图片网格和卡片列数能够适当增加。
- 页面留白和信息密度保持协调。

### 较窄窗口

- 侧边栏可以按照现有机制收起或压缩。
- 主内容能够采用适当的紧凑布局。
- 按钮、表单和导航项不会发生重叠。
- 关键操作仍然可见、可用。

实施要求：

- 优先使用 Flexbox、CSS Grid、minmax、min-width: 0、max-width 和合理的媒体查询。
- 只有在确实需要时才使用固定尺寸。
- 避免滥用绝对定位。
- 避免为每个页面设置彼此冲突的断点。
- 不要通过简单缩放整个界面解决适配问题。
- 不要在不清楚现有滚动机制的情况下随意增加 overflow: hidden。

请基于现有应用实际最小窗口尺寸与目标分辨率确定断点，不要凭空认定项目必须支持某个特定尺寸。

## 六、动效与交互设计

统一全局过渡效果，建立轻量、自然的交互体验。

建议：

- 按钮和图标的悬停反馈简洁。
- 弹窗和抽屉使用平滑但快速的进出动画。
- Tabs 切换反馈明确。
- 卡片悬停不应产生明显跳动。
- 加载状态不应阻塞不必要的交互。
- 状态变化尽量避免影响布局稳定性。

不要为了所谓的丝滑感而给所有元素添加动画。

优先使用 transform、opacity 等适合轻量过渡的属性，避免引入明显的性能负担。

应尊重系统的减少动态效果设置。

对于上传、图片生成、保存、删除等业务操作，应继续使用原有业务状态和反馈机制，不能只用定时器模拟成功。
